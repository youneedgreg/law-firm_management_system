# 14. Documentation that fails the build when it lies

**Status:** Accepted · **Date:** 2026-08-22

## Context

This repository argues that the reasoning behind a design is worth as much as
the design (ADR 0001). That argument only holds while the documents are true,
and documents rot in a way code does not: nothing breaks when a diagram becomes
wrong.

Phase 10 added the documents most prone to it. An entity-relationship diagram
after eighteen migrations. An architecture diagram of nine layers. A design
system page quoting contrast ratios. Each of those is a snapshot that is
accurate on the day it is committed and unfalsifiable afterwards — and a stale
diagram is worse than no diagram, because a reader believes it.

## Decision

A document that states a fact about the code is either **generated from the
code** or **checked against it by a test**. Prose about _why_ is exempt; claims
about _what_ are not.

| Document                | How it is held to the code                                                             |
| ----------------------- | -------------------------------------------------------------------------------------- |
| `docs/erd.md`           | Generated by `npm run docs:erd`; `erd.test.ts` regenerates and compares the whole page |
| `docs/architecture.md`  | `architecture.test.ts` checks every arrow against the linter's own boundary table      |
| `docs/design-system.md` | `tokens.test.ts` parses the real stylesheets and asserts the figures quoted            |
| The sign-in roster      | `demo.test.ts` checks every account against what the seed provisions                   |
| `README.md`             | Not checked — see below                                                                |

## Rationale

### Generated, and then checked that it was regenerated

Generating `docs/erd.md` is only half of it. A generated file nobody regenerates
is a hand-drawn file with extra steps, so `erd.test.ts` rebuilds the page from
the migrations and compares it byte for byte with what is committed. A migration
that adds a table and does not run the generator fails CI.

The generator applies the migrations to PGlite — Postgres compiled to
WebAssembly, in-process — rather than reading the live catalogue. That is
deliberate beyond convenience: a generator pointed at the deployed database
would document whatever happened to be there, including a migration somebody
applied by hand and never committed.

### Checking a diagram against the rules, not against a copy of them

The layer diagram could have been checked against a hard-coded list of allowed
edges, which would have been a second copy of the architecture and would have
drifted from the first. Instead the boundary table moved out of
`eslint.config.mjs` into `eslint.boundaries.mjs`, and both the linter and the
test read it. The linter enforces the layering; the test stops the picture of it
from claiming an edge the linter forbids.

The check is deliberately one-directional. It does not assert that every real
import is drawn — `app/` imports eight things and a complete diagram would be a
hairball nobody reads. The arrows are a summary; what is guaranteed is that the
summary is not false.

### Why the README is exempt

It is mostly argument, and an argument cannot be unit-tested. What it does state
factually — test counts, table counts — is either quoted from a command whose
output is in the same paragraph or is a number a reader can check in one click.
Asserting the README's prose would mean asserting sentences, which produces a
test that fails on rewording and passes on being wrong.

The honest version of this consequence: the README is the document most likely
to go stale here, and it is stale-prone precisely because it is the one nothing
holds. Phase 10 rewrote it once because it had already drifted two phases behind
the code.

## Consequences

- `docs/erd.md` is in `.prettierignore`. The formatter pads markdown tables,
  which would put the committed file permanently at odds with its own
  generator — so the generator's output is the format.
- `erd.test.ts` costs about three seconds of the default suite for a PGlite
  instance. `schema.test.ts` already pays the same, and the alternative is a
  diagram nobody trusts.
- A new `src/` directory fails `architecture.test.ts` until it is on the
  diagram, which is a small tax on adding a layer and the whole point of the
  test.
- Documents that state nothing checkable — the ADRs, `domain-notes.md` — are
  unaffected, and remain the ones a reader has to take on trust. `domain-notes.md`
  marks each entry ✅ verified against primary text or ⚠️ secondary, which is
  the closest a citation can come to a test.
